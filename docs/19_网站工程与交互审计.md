# 网站工程与交互审计

更新日期：2026-08-11

这份审计记录对应当前 `codex/blog-editorial-experience` 分支的实现状态。它不是设计稿，而是给后续内容更新、功能扩展和上线回归使用的维护清单。

## 已完成

### 结构与路由

- 静态路由已统一进入 `src/data/site-routes.ts`，sitemap 不再单独维护一份容易过期的页面列表。
- Blog、Projects、Skills、Lab 保留为一级内容入口，Photography 和 Architecture 作为档案入口。
- 缺失的 `/photos`、`/architecture`、`/blog/archive` 等页面已补齐到构建与 sitemap。
- sitemap 对文章使用 `updatedDate`，没有更新日期时才回退到 `pubDate`；静态页不伪造 `lastmod`。

### 交互与可访问性

- 移动导航现在支持点击展开、Escape 关闭、点击外部关闭、焦点回收和 Tab 循环。
- 桌面子菜单支持鼠标悬浮、Disclosure 按钮和键盘焦点进入，并使用 `inert` 防止隐藏菜单被读屏/键盘访问。
- 全站补充 skip link、`main-content` 锚点、按钮触摸尺寸、复制链接的状态反馈和文章目录当前项反馈。
- 外链统一使用 `noopener noreferrer`；链接箭头、返回箭头和首页符号改为 Lucide 图标，避免 Unicode 充当界面图标。
- Blog 精选舞台在运行时切换到外部文章时也保留 `noopener noreferrer`，不只保证首屏静态链接。
- 深色模式使用主题变量，支持手动切换、系统偏好和主题色同步；图片默认设置懒加载、异步解码和跨域 referrer 策略。

### 内容与 i18n

- Blog frontmatter 增加 `contentLanguage`、`coverAlt`、`externalLinks` 校验。
- `scripts/prepare-blog-content.mjs` 现在检查重复 slug、重复摘要、重复外链、封面描述和 `链接.txt` 与 frontmatter 的一致性；`--write` 只同步受管字段，不覆盖文章正文。
- 首页内容 schema 会校验必填字段和双语段落数量，缺失或错配时让构建直接失败，不再静默生成空内容。
- 页面 UI 文案使用 `LocalizedText`，导航文案集中在 `src/data/navigation.ts`，页面标题、description、OG/Twitter 文案会随语言切换同步更新。
- 首页动态背景切换按钮的 aria-label/title 也会跟随语言切换，不再由独立 WebGL 脚本覆盖成单一中文。
- Projects、Skills、Lab 的目录条目已集中到 `src/data/catalog.ts`，页面只保留布局和渲染逻辑。
- 首页中文/英文内容已迁移到 `content/site/home.json` 与 `home.en.json`，由 `src/lib/home-content.ts` 的 Zod schema 校验必填字段、URL、邮箱和双语段落数量。
- 图片组件支持 `data-alt-zh` / `data-alt-en`，摄影/建筑档案、精选封面和首页 hero 的 alt 会跟随 UI 语言切换。
- BlogPosting 增加 `inLanguage`、`datePublished` 和 `dateModified`。
- Markdown 正文图片会根据最近章节标题生成上下文 alt，并统一 loading/decoding 属性；内容作者仍应为每张图填写更具体的描述。

### 工具链

- `npm run build` 已串联 `blog:check`、`astro check` 和 `astro build`。
- `npm run build` 末尾会执行 `site:check`，检查关键静态路由、sitemap、内部链接与 fragment、main 锚点、图片 alt/懒加载、外链 rel 和一级导航面板数量。
- `npm run test:smoke` 会先构建静态产物，再启动临时静态服务器，使用本机 Edge 回归移动导航焦点、语言/主题切换、归档 Load more、文章复制链接和目录高亮；`site:check` 同时拒绝静态产物中的未转译 inline TypeScript 泛型。
- Astro Markdown 处理器已显式使用 `@astrojs/markdown-remark`，避免 Astro 7 的旧配置兼容警告。
- 原始照片归档与网站实际使用的 WebP 资产分开；未确认用途的原始 JPEG 没有自动纳入提交。

## 仍需关注

### P1：语言版本的 SEO 边界

当前 i18n 是客户端 UI 切换：首次 HTML、文章正文和文章标题仍以中文静态输出，英文在浏览器运行脚本后更新。它适合一个 URL 的双语阅读体验，但不是独立的英文 SEO 页面，因此暂不应添加伪造的 `hreflang`。

如果未来需要英文搜索流量，应把语言变成路由维度（例如 `/en/...`），并为标题、摘要、正文、canonical、sitemap 和 RSS 建立真正的双语内容源。

### P2：正文图片 alt 质量

构建插件会把空 alt 或旧的通用 `图像` 替换为最近章节标题加 `illustration`，避免积累无意义的通用 alt；发布前仍应把自动生成的 alt 视为待人工优化项。

### P2：资产清理决策

`src/assets/archive/photos/` 中仍有未跟踪的原始 JPEG。它们当前不是构建输入；后续应确认是否需要作为原图备份、迁移到外部存储，或由用户确认后清理，不能在自动提交时混入大文件。

## 每次内容更新建议

1. 新增文章目录和 `index.md` 后运行 `npm run blog:migrate`。
2. 运行 `npm run blog:check`，确认 slug、摘要、封面 alt、外链和分类无冲突。
3. 运行 `npm run build`，确认 Astro 类型检查和静态路由全部通过。
4. 检查生成页面的 canonical、`inLanguage`、`dateModified`、图片 alt 和外链 rel。
5. 在移动宽度检查导航、归档筛选、文章目录和复制链接反馈，再提交一个完整阶段。
