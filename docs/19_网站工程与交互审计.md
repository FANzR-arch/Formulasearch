# 网站工程与交互审计

更新日期：2026-08-11

这份审计记录对应当前 `codex/blog-editorial-experience` 分支的实现状态。它不是设计稿，而是给后续内容更新、功能扩展和上线回归使用的维护清单。

## 已完成

### 结构与路由

- 静态路由已统一进入 `src/data/site-routes.ts`，sitemap 不再单独维护一份容易过期的页面列表。
- Blog、Projects、Skills、Lab 保留为一级内容入口，Photography 和 Architecture 作为档案入口。
- 缺失的 `/photos`、`/architecture`、`/blog/archive` 等页面已补齐到构建与 sitemap。
- sitemap 对文章使用 `updatedDate`，没有更新日期时才回退到 `pubDate`；静态页不伪造 `lastmod`。
- RSS 路由 `/rss.xml` 仅输出 `contentStatus: full` 且非 draft 的本站文章，并通过构建检查和请求回归。

### 交互与可访问性

- 移动导航现在支持点击展开、Escape 关闭、点击外部关闭、焦点回收和 Tab 循环。
- 导航 disclosure 与移动端菜单的 `aria-label` 会随展开/收起和语言切换更新，屏幕阅读器不会继续把已展开菜单读成“打开”。
- 桌面子菜单支持鼠标悬浮、Disclosure 按钮和键盘焦点进入，并使用 `inert` 防止隐藏菜单被读屏/键盘访问。
- 全站补充 skip link、`main-content` 锚点、按钮触摸尺寸、复制链接的状态反馈和文章目录当前项反馈。
- 归档筛选与 Load more 分离维护“当前标签”和“已展开数量”，未来增加多标签筛选时不会把不匹配的记录重新显示。
- 归档渲染会按筛选结果重新计算匹配项序号和剩余数量；筛选结果少于当前展开数时不再显示无效的 Load more，也不会因原始索引靠后而把匹配项错误隐藏。
- 归档筛选与 Load more 增加双语 `aria-live` 结果状态，切换或加载后会播报当前显示数量与匹配总数。
- 外链统一使用 `noopener noreferrer`；链接箭头、返回箭头和首页符号改为 Lucide 图标，避免 Unicode 充当界面图标。
- Blog 精选舞台在运行时切换到外部文章时也保留 `noopener noreferrer`，不只保证首屏静态链接。
- Blog 精选舞台运行时如果目标数据缺失会移除详情链接的 `href`，不再生成 `#` 占位链接；该 fail-closed 行为有浏览器回归测试覆盖。
- 深色模式使用主题变量，支持手动切换、系统偏好和主题色同步；图片默认设置懒加载、异步解码和跨域 referrer 策略。
- 全站语言/主题状态机已抽到 `public/scripts/site-shell.js`，导航菜单、移动端焦点循环和语言按钮已抽到 `public/scripts/site-header.js`；Astro 模板只负责输出数据属性，后续交互修复可独立修改和缓存。
- Blog/Base layout 现在要求调用方显式提供中英文 title/description；未翻译文章会在文章 layout 里明确传入同一份原文，不再由布局层静默回退，新增页面缺少英文 metadata 会直接暴露。
- Blog 与 Catalog layout 共用 `src/components/SiteFooter.astro`，版权年份、站点名和返回首页文案只维护一份；variant 只负责保留现有视觉布局类名。

### 内容与 i18n

- Blog frontmatter 增加 `contentLanguage`、`coverAlt`、`externalLinks` 校验。
- Blog Content Collection 现在拒绝空白/重复 tags，以及同一篇文章重复的外链；迁移脚本也会拦截同篇重复外链，内容更新不会只在某一条检查路径上失败。
- Blog 列表、文章详情、sitemap 和 RSS 统一读取 Astro Content Collection，不再维护第二套 txt/frontmatter 解析器；分类仍由 `content/blog/categories.json` 统一映射，并通过单一 Zod 入口校验 ID、双语标题和描述，未知分类会在构建时失败。
- `scripts/prepare-blog-content.mjs` 现在检查重复 slug、重复摘要、重复外链、封面描述和 `链接.txt` 与 frontmatter 的一致性；`--write` 只同步受管字段，不覆盖文章正文。`--check` 还会按 `full` / `index-only` / `draft` 输出数量：已发布的 `index-only` 必须保留外链，`full` 必须有非空正文；缺少可靠来源的记录应标为 `draft: true`，不会进入公开 Blog 列表。
- Blog `slug` 现在由 Content Collection 强制使用小写字母、数字和连字符，避免新增内容把空格或特殊字符带进 canonical、sitemap 和 RSS。
- 所有会渲染为链接的内容字段（文章来源、首页社交链接、站点 URL、作者 URL、GitHub URL）统一使用 `src/lib/validation.ts` 的 `httpUrlSchema`，只允许 `http/https` 协议。
- 浏览器主题色的 light/dark 值已迁移到 `content/site/site.json`，SSR `<meta name="theme-color">` 与客户端切换脚本共享同一配置，不再在模板脚本中重复硬编码。
- `scripts/import-blog-bodies.mjs` 默认不会覆盖已有 `full` 正文，只有显式传入 `--overwrite` 才会替换；预检/写入输出会报告跳过数量，降低误覆盖风险。
- 首页内容 schema 会校验必填字段和双语段落数量，缺失或错配时让构建直接失败，不再静默生成空内容。
- 首页双语 schema 还会校验 email、社交账号、社交 URL 和 heroImage 这类共享字段保持一致；模板不会再只读取中文文件却允许英文文件悄悄漂移。
- 首页模板不再在中英文段落数量不一致时静默回退中文；基础布局也要求调用方显式提供 title 和 description，新增页面缺少 SEO 文案会在 Astro 类型检查阶段暴露。
- 首页联系区的标题和邮件前缀已进入 `home.json` / `home.en.json`，页面不再内联维护这组双语文案。
- 页面 UI 文案使用 `LocalizedText`，导航和下拉菜单内容来自 `content/site/navigation.json`，页面标题、description、OG/Twitter 文案会随语言切换同步更新。

- 首页、站点配置、页面 metadata、博客主题/分类/媒体、导航、目录和摄影/建筑档案 manifest 也统一使用 strict object；内容字段的新增、删除或拼写变化必须同步更新 schema，不会再被运行时静默忽略。
- Blog 最新 / 主题 / 归档子导航已迁移到 `content/site/blog-navigation.json`；组件不再内联维护路径和中英文文案，构建会校验 ID 与路由一致。
- 全站下拉导航的 hash 链接现在会和 Blog 主题、Projects、Skills、Lab manifest 的真实 section ID 交叉校验；新增或重命名区块时不会留下静默断链。
- Blog 工具栏、入口页导语/区块标题、归档控件、来源平台、相关文章和常用返回操作已集中到 `content/site/ui-copy.json`，组件不再重复维护同一组 UI 文案。

### 工具链

- `npm run build` 已串联 `blog:check`、`blog:images:check`、`astro check` 和 `astro build`。
- `npm run check` 使用与构建相同的 telemetry-disabled wrapper，单独运行 Astro 类型检查不会因用户目录写权限失败。
- `npm run build` 还会执行 `blog:media:check`，确认封面文件与尺寸清单没有漂移；新增或替换封面后先运行 `npm run blog:media:prepare`。
- `npm run site:check` 现在会逐页检查 `main` / `h1` 的唯一性、按钮可访问名称，以及 `aria-controls` / `aria-labelledby` 是否指向真实节点；这类结构回归不会等到人工打开每个页面才被发现。
- 具有 `aria-label` 的普通内容容器现在显式声明 `role="group"`，并由 `site:check` 防止后续新增“标签存在但语义被浏览器忽略”的容器。
- `npm run build` 末尾会执行 `site:check`，检查关键静态路由、每篇 full 文章是否进入 HTML/sitemap/RSS、canonical/title/description/OG 类型、内部链接与 fragment、main 锚点、图片 alt/懒加载、`img/srcset` 本地资产、外链 rel、一级导航面板数量，并确认 `draft: true` 或 `index-only` 文章不会进入 sitemap 或 RSS。
- `site:check` 同时校验 `robots.txt` 的公开规则/Sitemap 地址，以及 `llms.txt` 是否与一级静态入口双向一致；新增和删除路由都会在构建时暴露，避免发布辅助入口悄悄过期。
- `npm run test:smoke` 会先构建静态产物，再启动临时静态服务器，使用本机 Edge 回归移动导航焦点、语言/主题切换、归档 Load more、文章复制链接和目录高亮；`site:check` 同时拒绝静态产物中的未转译 inline TypeScript 泛型。
- `scripts/serve-dist.mjs` 的预览服务器现在按真实路径分隔符校验 `dist` 边界，并把非法编码 URL 返回为 400；回归测试会确认路径越界不会读到项目外文件。
- Astro Markdown 处理器已显式使用 `@astrojs/markdown-remark`，避免 Astro 7 的旧配置兼容警告。
- 原始照片归档与网站实际使用的 WebP 资产分开；未确认用途的原始 JPEG 没有自动纳入提交。
- `content/README.md` 与各内容 manifest 的维护说明已同步到当前实现，避免把已迁移的数据入口误标成“尚未接入”。

## 仍需关注

### P1：语言版本的 SEO 边界

当前 i18n 是客户端 UI 切换：首次 HTML、文章正文和文章标题仍以中文静态输出，英文在浏览器运行脚本后更新。它适合一个 URL 的双语阅读体验，但不是独立的英文 SEO 页面，因此暂不应添加伪造的 `hreflang`。

如果未来需要英文搜索流量，应把语言变成路由维度（例如 `/en/...`），并为标题、摘要、正文、canonical、sitemap 和 RSS 建立真正的双语内容源。

### P2：正文图片 alt 质量（基础门禁已完成）

现有文章的通用 alt 已替换为章节上下文描述，构建插件和 `blog:images:check` 会阻止新的通用 alt 进入发布流程；`blog:images:report` 会列出仍使用“章节标题 + 配图”初稿的图片，方便内容更新时集中人工复核。复杂图像的视觉细节仍需人工逐张优化，报告不会假装替代视觉判断。

### P2：Blog 图片传输优化

本阶段已补齐封面固有尺寸，并生成 80 个响应式 WebP 变体（当前约 2.99 MB，原始封面约 13.18 MB）；页面通过 `<picture>` / `srcset` 按视口选择资源，原图保留为兼容回退。后续可在确认缓存、存储和发布策略后评估 AVIF 或 Astro 图片管线，但不应再手工维护图片路径。

### P2：资产清理决策

`src/assets/archive/photos/` 中的原始 JPEG 已加入 `.gitignore`，不会在自动提交时混入大文件；它们当前不是构建输入，后续仍应确认是否需要作为原图备份或迁移到外部存储。

## 每次内容更新建议

1. 新增文章目录和 `index.md` 后运行 `npm run blog:migrate`。
2. 为正文图片填写具体 alt；旧文章可运行一次 `npm run blog:images:prepare` 生成章节上下文初稿，再用 `npm run blog:images:report` 找出需要人工复核的图片。
3. 运行 `npm run blog:check` 和 `npm run blog:images:check`，确认 slug、摘要、封面 alt、正文图片 alt、外链和分类无冲突。
4. 新增或替换封面后运行 `npm run blog:media:prepare`，确认尺寸清单更新。
5. 运行 `npm run build`，确认 Astro 类型检查和静态路由全部通过。
6. 检查生成页面的 canonical、`inLanguage`、`dateModified`、图片 alt 和外链 rel。
7. 在移动宽度检查导航、归档筛选、文章目录和复制链接反馈，再提交一个完整阶段。
