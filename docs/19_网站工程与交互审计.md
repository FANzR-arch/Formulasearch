# 网站工程与交互审计

更新日期：2026-08-12

这份审计记录对应当前 `codex/blog-editorial-experience` 分支的实现状态。它不是设计稿，而是给后续内容更新、功能扩展和上线回归使用的维护清单。

## 已完成

### 结构与路由
- English SSR 路由已接入：`site-routes.json` 的 `localized` 清单驱动 `/en`、`/en/projects`、`/en/skills`、`/en/lab`、`/en/photos`、`/en/architecture` 及 Blog 三个索引页；输出检查会验证这些页面存在并进入 sitemap/llms。

- 静态路由与 RSS、Sitemap、LLM 页面入口统一维护在 `content/site/site-routes.json`；`src/data/site-routes.ts` 负责 Zod 校验并导出类型化访问，模板、结构化数据和输出检查复用同一份 manifest，内容 JSON 只负责可编辑的导航文案与 hash。
- 路由 manifest 将页面静态路由与 RSS/Sitemap/LLM 文件路由分开校验，并要求页面清单完整且无重复，避免内容更新时把文件端点误当作 HTML 页面加入 sitemap。
- Blog、Projects、Skills、Lab 保留为一级内容入口，Photography 和 Architecture 作为档案入口。
- 缺失的 `/photos`、`/architecture`、`/blog/archive` 等页面已补齐到构建与 sitemap。
- sitemap 对文章使用 `updatedDate`，没有更新日期时才回退到 `pubDate`；静态页不伪造 `lastmod`。
- RSS 路由 `/rss.xml` 仅输出 `contentStatus: full` 且非 draft 的本站文章，并通过构建检查和请求回归。

### 交互与可访问性

- 移动导航现在支持点击展开、再次点击按钮关闭、Escape 关闭、点击外部关闭、焦点回收和 Tab 循环；全局外部点击监听不会误吞掉菜单按钮自己的 click。
- 导航 disclosure 与移动端菜单的 `aria-label` 会随展开/收起和语言切换更新，屏幕阅读器不会继续把已展开菜单读成“打开”。
- 桌面端导航通过键盘打开后，焦点离开导航区域会自动收起菜单并恢复 `inert`；不会在焦点已经移到语言 / 主题工具栏时继续悬浮。
- 下拉菜单的鼠标离开延迟不会抢先关闭仍有键盘焦点的菜单项；焦点离开后才允许恢复 hover 收起行为。
- 导航 disclosure 额外声明 `aria-haspopup="true"`，辅助技术能明确识别触发器会展开关联菜单；`aria-expanded`、`aria-controls` 与浏览器回归共同覆盖状态变化。
- 桌面子菜单支持鼠标悬浮、Disclosure 按钮和键盘焦点进入，并使用 `inert` 防止隐藏菜单被读屏/键盘访问。
- 全站补充 skip link、`main-content` 锚点、按钮触摸尺寸、复制链接的状态反馈和文章目录当前项反馈。
- 归档筛选与滚动渐进加载分离维护“当前标签”和“已展开数量”，未来增加多标签筛选时不会把不匹配的记录重新显示。
- 归档渲染会按筛选结果重新计算匹配项序号和剩余数量；筛选结果少于当前展开数时不会继续触发无效的滚动加载，也不会因原始索引靠后而把匹配项错误隐藏。
- 归档筛选与滚动自动加载增加双语 `aria-live` 结果状态，筛选或加载后会播报当前显示数量与匹配总数；不支持 `IntersectionObserver` 或关闭 JavaScript 时会直接显示全部记录，避免渐进加载造成不可达内容。
- Photography/Architecture 的模式导航和头部归档图标现在同时输出 `aria-current="page"`；视觉 active 状态与屏幕阅读器的当前页语义保持一致，并由 `site:check` 与浏览器回归覆盖。
- 外链统一使用 `noopener noreferrer`；链接箭头、返回箭头和首页符号改为 Lucide 图标，避免 Unicode 充当界面图标。
- Blog 精选舞台在运行时切换到外部文章时也保留 `noopener noreferrer`，不只保证首屏静态链接。
- Blog 精选舞台运行时如果目标数据缺失会移除详情链接的 `href`，不再生成 `#` 占位链接；该 fail-closed 行为有浏览器回归测试覆盖。
- Blog 精选舞台切换文章或语言时只更新当前语言子节点，不会用 `textContent` 覆盖 `LocalizedText` 的双语 DOM；标题、摘要和分类会保留正确的 `lang` 标记和后续语言切换能力。
- 头部 Logo、导航 disclosure、归档入口、语言/主题按钮以及归档模式/筛选控件统一扩大到至少 40px 的可点击区域（归档筛选为 44px）；移动菜单按钮与文章复制链接按钮补齐 `:focus-visible`，键盘用户不会丢失当前焦点位置。
- 工具栏按钮保留统一的 40px 点击盒，同时归档、GitHub、语言和主题图标统一在约 17px 的视觉尺寸；点击面积与图标面积分离，避免主题图标因 `width: 100%` 撑满按钮而显得突兀。
- 首页 WebGL 上下文丢失时会停止 requestAnimationFrame 动画并切换 CSS ambient fallback；不会继续对失效 context 调用绘制 API，也不会因为背景层故障阻塞正文。
- 首页背景在页面进入后台时会取消动画帧，回到前台才恢复；隐藏标签页不会继续保留无效的 requestAnimationFrame 链。
- 深色模式使用主题变量，支持手动切换、系统偏好和主题色同步；图片默认设置懒加载、异步解码和跨域 referrer 策略。
- 浅色站点与归档主题 token 已通过构建期对比度门禁；全局 `--muted` 从约 4.40:1 调整到约 4.59:1，普通正文不再卡在 WCAG AA 4.5:1 边界下方。
- 全站语言/主题状态机已抽到 `public/scripts/site-shell.js`，导航菜单、移动端焦点循环和语言按钮已抽到 `public/scripts/site-header.js`；Astro 模板只负责输出数据属性，后续交互修复可独立修改和缓存。
- 归档筛选/滚动渐进加载、Blog 精选舞台和文章复制/目录高亮脚本也已移到 `public/scripts/archive-index.js`、`public/scripts/blog-index.js` 与 `public/scripts/article-page.js`；页面模板只保留 data 属性契约，三个页面脚本可独立做语法检查和浏览器缓存。
- Blog/Base layout 现在要求调用方显式提供中英文 title/description；未翻译文章会在文章 layout 里明确传入同一份原文，不再由布局层静默回退，新增页面缺少英文 metadata 会直接暴露。
- Blog 与 Catalog layout 共用 `src/components/SiteFooter.astro`，版权年份、站点名和返回首页文案只维护一份；variant 只负责保留现有视觉布局类名。
- 首页中英文入口现在共同使用 `SiteFooter`；页脚样式归入全站 `global.css`，不再只有英文首页输出组件、却依赖未加载的 Blog CSS。
- Projects、Skills、Lab 共用 `src/components/CatalogIndex.astro` 输出 hero、目录索引和 section 列表；页面文件只选择对应 manifest 数据与 active 路由，目录结构和可访问性修复不再复制三份。
- Catalog hero 的介绍文案使用语义化 `<p class="catalog-hero__intro">`，不再用 `<span>` 承载段落；共享组件与响应式 CSS 选择器保持一致。
- Photography 与 Architecture 归档共用 `src/data/archive-schema.ts` 的布局、筛选器、页面策略和关系校验；新增归档类型时只需补充媒体来源与特有字段，不再复制重复的 Zod/重复 index/image/filter 检查。

### 内容与 i18n
- 默认中文 URL 继续支持客户端双语切换；已有双语数据的页面同时具备真实英文 HTML、`lang="en"`、英文 metadata、canonical 与 reciprocal hreflang。Blog 中文正文没有英文源时，English 索引链接回中文文章 URL，不生成伪造的 `/en/blog/:slug`。

- Blog frontmatter 增加 `contentLanguage`、`coverAlt`、`externalLinks` 校验。
- Blog frontmatter 的 `updatedDate` 现在必须不早于 `pubDate`；修改日期倒退会在 Content Collection 构建期失败，避免 sitemap、RSS 和 JSON-LD 出现时间倒退。
- Blog `cover` 现在必须是单斜杠开头的站内资源路径；协议相对路径、外部 URL 或空值会在内容构建期失败，不会等到 `<picture>` 渲染时才暴露。
- Blog 迁移脚本明确区分“源文件夹日期”和文章 `pubDate`：已有 `index.md` 的真实发布日期不会被同步脚本覆盖；新建索引才暂以源文件夹日期作为待核验默认值，避免后续维护者误把资源配对键当成发布日期。
- Blog Content Collection 现在拒绝空白/重复 tags，以及同一篇文章重复的外链；迁移脚本也会拦截同篇重复外链，内容更新不会只在某一条检查路径上失败。
- 外链平台在 frontmatter 中使用稳定 ID（`wechat` / `x` / `original`），显示文案集中维护在 `content/site/ui-copy.json`，避免把中文界面文案当作数据枚举。
- Blog 列表、文章详情、sitemap 和 RSS 统一读取 Astro Content Collection，不再维护第二套 txt/frontmatter 解析器；分类仍由 `content/blog/categories.json` 统一映射，并通过单一 Zod 入口校验 ID、双语标题和描述，未知分类会在构建时失败。
- `scripts/prepare-blog-content.mjs` 现在检查重复 slug、重复摘要、重复外链、封面描述和 `链接.txt` 与 frontmatter 的一致性；`--write` 只同步受管字段，作者维护的 `coverAlt` / `coverAltEn` 与文章正文都不会被覆盖。`--check` 还会按 `full` / `index-only` / `draft` 输出数量：已发布的 `index-only` 必须保留外链，`full` 必须有非空正文；缺少可靠来源的记录应标为 `draft: true`，不会进入公开 Blog 列表。
- `blog:check` 与 Content Collection 现在共享英文文章的前置约束：`contentLanguage: en` 缺少 `titleEn`、`descriptionEn` 或 `coverAltEn` 会在内容检查阶段直接失败，不必等到最终构建。
- Blog `slug` 现在由 Content Collection 强制使用小写字母、数字和连字符，避免新增内容把空格或特殊字符带进 canonical、sitemap 和 RSS。
- Blog `slug` 还会从 `src/data/site-routes.ts` 派生保留路由，拒绝 `series` / `archive` 等静态 Blog 页面 slug，避免动态文章页覆盖固定入口。
- 所有会渲染为链接的内容字段（文章来源、首页社交链接、站点 URL、作者 URL、GitHub URL）统一使用 `src/lib/validation.ts` 的 `httpUrlSchema`，只允许 `http/https` 协议。
- 浏览器主题色的 light/dark 值已迁移到 `content/site/site.json`，SSR `<meta name="theme-color">` 与客户端切换脚本共享同一配置，不再在模板脚本中重复硬编码。
- `scripts/import-blog-bodies.mjs` 默认不会覆盖已有 `full` 正文，只有显式传入 `--overwrite` 才会替换；预检/写入输出会报告跳过数量，降低误覆盖风险。
- 首页内容 schema 会校验必填字段和双语段落数量，缺失或错配时让构建直接失败，不再静默生成空内容。
- 首页双语 schema 还会校验 email、社交账号、社交 URL 和 heroImage 这类共享字段保持一致；模板不会再只读取中文文件却允许英文文件悄悄漂移。
- 首页双语 schema 会同时校验 `intro` / `about` / `interest` / `identity` / `now` / `work` 的条目数量，以及姓名、邮箱、社交账号和 heroImage 这类共享字段；heroImage 为空时也不会遗留孤立 alt。
- 首页模板不再在中英文段落数量不一致时静默回退中文；基础布局也要求调用方显式提供 title 和 description，新增页面缺少 SEO 文案会在 Astro 类型检查阶段暴露。
- 首页联系区的标题和邮件前缀已进入 `home.json` / `home.en.json`，页面不再内联维护这组双语文案。
- 页面 UI 文案使用 `LocalizedText`，导航和下拉菜单内容来自 `content/site/navigation.json`，页面标题、description、OG/Twitter 文案会随语言切换同步更新。
- Blog 文章可选维护 `titleEn` / `descriptionEn`；列表、精选舞台、相关阅读和 metadata 会优先使用英文字段，缺失时回退原始内容，避免后续补译时重复改模板。
- `LocalizedText` 支持独立的实际文本语言标记；中文文章缺少 `titleEn` / `descriptionEn` 时，即使 UI 切到英文，fallback 内容仍标记为 `zh-Hans`，不会把中文误声明为英文。
- 导航、页面 metadata、Blog 分组、档案和共享 UI manifest 的 `{ zh, en }` 字段共用 `src/lib/i18n.ts` 的 `localizedCopySchema`，避免不同数据模块各自复制一套双语必填规则。
- 双语文案和共享 UI copy schema 现在使用 strict object；误拼或遗留字段不会被 Zod 静默丢弃，内容更新会在构建阶段暴露。
- `localizedCopySchema` 还会先 trim 再检查非空，只有空格的中英文标签、标题或描述不能进入页面。
- 首页、站点配置、页面 metadata、博客主题/分类/媒体、导航、目录和摄影/建筑档案 manifest 也统一使用 strict object；内容字段的新增、删除或拼写变化必须同步更新 schema，不会再被运行时静默忽略。
- Blog 最新 / 主题 / 归档子导航已迁移到 `content/site/blog-navigation.json`；组件不再内联维护路径和中英文文案，构建会校验 ID 与路由一致。
- 全站下拉导航的 hash 链接现在会和 Blog 主题、Projects、Skills、Lab manifest 的真实 section ID 交叉校验；新增或重命名区块时不会留下静默断链。
- Blog 工具栏、入口页导语/区块标题、归档控件、来源平台、相关文章和常用返回操作已集中到 `content/site/ui-copy.json`，组件不再重复维护同一组 UI 文案。
- 导航分类展开/子菜单、GitHub 个人链接和文章阅读时长使用 `ui-copy.json` 的占位模板，并通过 `src/lib/i18n.ts` 统一插值；作者署名与首字母标记读取 `site.json`，不再在模板中硬编码。
- 精选舞台和文章详情封面现在直接使用文章 frontmatter 的 `coverAlt`；如果确实有英文视觉描述，可额外填写 `coverAltEn`，没有翻译时保留原始内容语言，不再自动生成泛化的 `Article cover`。
- `coverAlt` / `coverAltEn` 现在会拒绝以“文章封面”或 `Article cover` 结尾的通用占位；新增文章必须在构建前补充可感知的画面描述，避免图片 alt 质量随内容更新回退。
- `ui-copy.json` 的中英文占位符集合与调用时的插值参数都在构建期校验，缺少 `{title}` / `{minutes}` 等参数会直接失败，不会把模板 token 静默输出到页面。
- 文章复制链接反馈保留中英文节点，仅切换复制状态；切换语言不会再把反馈节点替换成不可维护的纯文本。
- 文章复制失败不再调用阻塞式 `window.prompt`；失败状态直接显示在按钮内部，并复用双语 UI manifest，避免浏览器权限异常时打断阅读流程。
- 首页动态背景切换按钮的 aria-label/title 也会跟随语言切换；变体名称由 `ui-copy.json` 的 manifest 传给脚本，切换句式也来自同一文件，WebGL 脚本不再持有用户可见的中英文硬编码或重复 data 属性。
- Projects、Skills、Lab 的目录条目和页面级文案已集中到 `content/site/catalog.json`，页面只保留布局和渲染逻辑。
- 首页中文/英文内容已迁移到 `content/site/home.json` 与 `home.en.json`，由 `src/lib/home-content.ts` 的 Zod schema 校验必填字段、URL、邮箱和双语段落数量。
- 首页与 Blog 三个入口页的 SEO 标题/description 已迁移到 `content/site/page-meta.json`，由 `src/data/page-meta.ts` 校验，页面不再各自维护同一组 metadata。
- 图片组件支持 `data-alt-zh` / `data-alt-en`；摄影/建筑档案和首页 hero 始终提供双语 alt，Blog 封面只有在文章提供 `coverAltEn` 时才切换英文，否则保留原始内容语言。
- 首页 hero 图片现在要求在内容文件中提供双语 `heroImageAlt`；不再允许页面组件用统一的“首页图片”占位描述。
- 首页 hero 图片如果启用，还必须同时提供正整数 `heroImageWidth` / `heroImageHeight`；页面会输出固有尺寸，`site:check` 会防止后续内容更新重新引入布局偏移。
- Photography 和 Architecture 的页面文案、筛选器、标签及图片资源映射已集中到 `content/site/photo-archive.json`、`content/site/architecture.json`，并在构建时校验重复索引、资源和筛选器 ID。
- Photography 和 Architecture 的筛选器文案现在共用 `localizedCopySchema`，统一执行中英文 trim/非空校验；新增筛选器字段时不再维护两套 `{ zh, en }` 规则。
- Photography 和 Architecture 的筛选器首项必须是 `all`，其他筛选器必须至少命中一个条目 tag；`site:check` 还会逐页确认生成 HTML 的本地图片确实存在，避免 manifest 或发布资产漂移成 404。
- Photography 和 Architecture 的首屏显示数量、滚动渐进加载批次与图片首屏优先加载数量已进入各自 manifest；`ArchiveIndex` 不再通过 `active === 'photos'` 和固定数字推断分页策略，内容更新只需调整清单配置。
- 公开图片路径共用 `localAssetPathSchema`，只接受单斜杠站内绝对路径；协议相对 URL 不会绕过本地资源存在性检查。
- Blog 主题分组已集中到 `content/site/blog-series.json`，会校验唯一主题 ID 和分类 ID 是否真实存在；导航、目录和照片清单也会校验重复 ID、路由和公开资源路径。
- 相关内容推荐会使用 `blog-series.json` 的分类→主题映射作为历史文章的 series 兜底；新文章可以继续用 frontmatter 的 `series` / `tags` 做更精细的加权，不会因为旧文章字段为空而失去主题关联。
- BlogPosting 增加 `url`、`articleSection`、`inLanguage`、`datePublished` 和 `dateModified`，并与指向 Blog 主题页的 `BreadcrumbList` 一起输出；文章 HTML 同步输出 `article:published_time` / `article:modified_time`。
- JSON-LD 的 Blog/分类 Breadcrumb 与 `articleSection` 现在按文章 `contentLanguage` 选择双语文案，避免未来英文文章生成中英混杂的结构化数据。

## 仍需关注

### P1：语言版本的 SEO 边界

当前 i18n 分为两层：默认路由继续支持客户端双语切换；`site-routes.json` 的 `localized` 页面同时提供 `/en/...` 的 SSR 英文入口，并由 `BaseLayout` 输出 reciprocal hreflang。这样不会把浏览器脚本切换误当成 SEO 翻译。

English 静态页面已经具备路由维度；当前仍未为 25 篇中文正文生成 `/en/blog/:slug`，因为没有真实英文正文源。若未来需要英文文章搜索流量，应先补齐正文翻译，再扩展文章 canonical、sitemap 和 RSS，而不是复制中文正文。

英文文章的数据契约已补强：`contentLanguage: en` 现在必须同时提供 `titleEn`、`descriptionEn` 和 `coverAltEn`；BlogPosting 结构化数据也会按文章语言选择对应标题与摘要。当前 English SSR 只覆盖索引页；中文文章详情仍以中文 URL 和 `zh-Hans` 正文语言发布。

正文迁移预检仍保持 16 篇 `full`、10 篇 `index-only`；对本机 Philthink `02-已发布` 目录执行导入预检时，只有现有 16 篇能通过来源 URL/标题唯一匹配，剩余 10 篇没有可靠的已发布原稿，因此继续保留外链或草稿状态，不用素材区剪辑冒充正式正文。

### P2：正文图片 alt 质量（基础门禁已完成）

现有文章正文的通用 alt 已替换为章节上下文描述，构建插件和 `blog:images:check` 会阻止新的通用 alt 进入发布流程；当前 `blog:images:report` 仍列出 168 张“章节标题 + 配图”初稿。它们需要结合实际画面逐张改成具体描述，复杂图像的视觉判断不能由报告替代。

### P2：正文图片的外部依赖与固有尺寸

当前检查发现 170 个唯一 HTTPS 正文图片 URL，全部来自 `pbs.twimg.com`，`blog-image-dimensions.json` 已确认 0 个、待确认 170 个。本机 PowerShell 与 Edge 运行时均无法完成这些 URL 的图片请求，因此没有写入猜测尺寸；线上环境是否可访问仍需单独验证。它们已经逐张强制 lazy loading、异步解码和 no-referrer，但外部服务变慢、失效或返回尺寸未知时仍可能造成布局偏移。要彻底解决，需要明确“镜像到站内并生成尺寸清单”或“接受外部托管并维护远程尺寸 manifest”中的一种策略；在没有来源授权和存储决策前，不凭空写假尺寸。

### P2：Blog 图片传输优化（本阶段已完成）

本阶段已补齐封面固有尺寸，并生成 80 个响应式 WebP + 80 个 AVIF 变体（WebP 约 2.99 MB、AVIF 约 1.70 MB，原始封面约 13.18 MB）；页面通过 `<picture>` 按 AVIF → WebP → 原图回退，并用 `srcset` 按视口选择资源。后续只需评估是否迁移到 Astro 图片管线，不应再手工维护图片路径。

### P2：资产清理决策

`src/assets/archive/photos/` 中的原始 JPEG 已加入 `.gitignore`，不会在自动提交时混入大文件；它们当前不是构建输入，后续仍应确认是否需要作为原图备份或迁移到外部存储。

## 每次内容更新建议

1. 新增文章目录和 `index.md` 后运行 `npm run blog:migrate`。
2. 为正文图片填写具体 alt；旧文章可运行一次 `npm run blog:images:prepare` 生成章节上下文初稿，再用 `npm run blog:images:report` 找出需要人工复核的图片。
3. 运行 `npm run blog:check` 和 `npm run blog:images:check`，确认 slug、摘要、封面 alt、正文图片 alt、外链和分类无冲突。
4. 新增或替换封面后运行 `npm run blog:media:prepare`，确认尺寸清单更新。
5. 运行 `npm run build`，确认 Astro 类型检查和静态路由全部通过。
6. 检查生成页面的 canonical、`inLanguage`、`dateModified`、图片 alt 和外链 rel。
7. 在移动宽度检查导航、归档筛选、文章目录和复制链接反馈，再提交一个完整阶段。
