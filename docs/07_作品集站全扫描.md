## A 组 · 结构最值得抄（解决「内容类型多」）

### ⭐ [zefs.website](http://zefs.website/)
按**雇主 / 项目群**分组，每组标题后面跟一句自嘲式引号说明：

```
GoMore          — "Airbnb for cars"
  Ratings'24 · Product design'19—now · Brand design'19—now
The Guardian    — "That liberal newspaper"
  Header'17—'18 · Editorial design'16—'19 · Design system'16—'19
Personal projects — "Laughing at my own jokes"
  Good mourning'24 · Log flumes'14—now · McKatsu'14
```

**可抄的具体做法：** ① 分组标题带一句人话解释（外行也知道 GoMore 是什么）；② 每条带年份区间，`'19—now` 直接表达"还在做"；③ **个人项目和商业项目同页不同组**——正好是阿哲「业务 vs 表达」双身份的解法。

### ⭐ [calebbarclay.com](https://www.calebbarclay.com/)
一句话身份 + 实时时钟 + **一个叫 Revisions 的列表，把这个网站自己的每一次迭代编号列出来**：

```
1  Time-of-day gradient; clock centered           7-09
2  Scrub slider; continuous sky blending          7-09
3  Time labels hidden; reveal on change           7-10
4  Cursor light streak, reeded glass              7-11
5  Set in Super Display & Haptik                  7-12
```

**可抄的具体做法：把网站自己的构建过程当成内容。** 阿哲卖建站服务、又在做「把实践沉淀成资产」——这个站本身就是最好的样品，迭代日志就是最好的证明。底部还写明用了 Grilli Type 的哪两款字体。

### ⭐ [nathansmith.design](https://nathansmith.design/)
首页顶部是一条**动态流**，每条带缩略图 + 类型标签（Update / Press / Award），点开是外链：

```
[图] Update  Partner / Creative Director of Studio Kiln
[图] Press   TDC: The World's Best Typography 45
[图] Award   ADC Gold Cube win for RTS project
[图] Award   3x D&AD Pencil win for RTS project
                                              Show less
```

下面才是 Projects 网格 / Archive / Info 三个入口。**「最近发生什么」和「作品」分层**，动态流让站看起来是活的，而不用改作品集。

### [taliacotton.com](https://taliacotton.com/)（已在 02 登记）
一个人 12 类内容装一页。内容类型比阿哲还多。

## B 组 · 条目信息设计（一个条目里塞多少信息）

### ⭐ [belentenorio.com](http://www.belentenorio.com/)
每个作品条目是**四行结构 + 一个 GIF 缩略图**：

```
[GIF]  Apple
       Apple
       Web and Mweb
       Product
```
（项目名 / 客户 / 平台 / 角色）

**密度和视觉同时拿到。** 而且是纯静态 `.html`（`applelogo.gif`、`p100cover.gif` 这种），零框架、极轻。用 GIF 而非静态图做缩略图，给页面动感但不需要视频。

### [elenamiska.com](https://elenamiska.com/)
条目 = 标题 + 类型 + 缩略图 + **一句话说明作品是什么**：
> Echoes of Ailey — 惠特尼美术馆展览影片的片头，主角是 Alvin Ailey 舞团的舞者 — Title Design

比纯图网格多一层信息，不用点进去就知道是什么。

### [henryslaughter.ca](https://henryslaughter.ca/)
条目 = 项目名 + 逗号分隔的服务类型。最省字的写法：
> Ology — Brand identity, Graphics, Website design
> Minicircle — Content, Graphics, Merch

顶部挂一个 RGD Ultrabold Awards 的 Winner 徽标。

### [aristidebenoist.com](https://www.aristidebenoist.com/)
项目信息用 **A / B / C / D 编号标注**，像技术规格表：`COMPLETED` `TYPE` `ROLE` `CLIENT`。独立开发者，规格表美学。

### ⭐ [catherinebui.com](https://catherinebui.com/) —— 业务页最该抄这个
一句话身份（freelance designer and front-end developer in Portland, Oregon）+ Selected work，每条是「客户名 + 我做了什么 + 网站截图」，**链接直接指向真实上线的站**：

```
Joshuvela  Web design and development     → joshuvela.com
Figma      Web design and illustrations    → figma.com/figjam
RtA        Web design and development      → rtabrand.com
GitHub     Web design and development      → github.com/mobile
VSCO       Web development                 → vsco.co
```

**做建站的人怎么展示建站作品：不写 case study，直接放线上站。** 阿哲有水土营造、建筑师&艺术家官网、SyntaxStudio，可以照这个排。

## C 组 · 「名片 = 关于」的几种写法

### [aarongarzadesign.com](https://aarongarzadesign.com/)
**整个首页就是一段排版过的自我介绍**，没有作品网格。履历写成正文，关键词直接内链（Pentagram、New York Magazine、Phaidon、Abrams、Rizzoli）。结尾一句：「目前接受工作或项目咨询，邮件 hi@…」。
极端「文字即首页」，靠排版和字距处理避免单调。

### [sarahsampsel.com](http://sarahsampsel.com/)
简历式：`Hi, I'm Sarah.` + 一段定位（现在在 Airbnb，之前 Work & Co / Huge / 华盛顿邮报）+ 按公司分段的经历，每段列职位、时间、做了什么、客户。

### [jenniferheintz.com](https://jenniferheintz.com/)
最短的一版，一屏完：一段自我介绍（还提到"她马上要当妈妈了"）+ **Recognition 奖项列表** + 联系方式。奖项只列名字不列年份。

### [joshpensky.com](https://joshpensky.com/)
About + Work（倒序编号 + 年份区间）。项目下面挂**媒体报道链接**（App Store、Tom's Guide、Lifehacker、TechRadar、The Verge）当背书。定位词是 "design engineer"。

### [earvin.ca](https://www.earvin.ca/)
纯文字自我介绍 + Select clients 名单。定位一句话写在标题里：`Visual Design Lead at Google DeepMind`。

### [marinarachello.com](https://marinarachello.com/)
名字玩梗当大标题：`Marina Rac-hello!`。下面小标题 `Some things that I have designed`。

## 扫完的三条总结

**① 没有一个用独立封面页。** 40 个全部首页即入口。加上前一批的 sive.rs / rsms.me / 100r.co / manuelmoreale，一共 44 个站，零封面页。

**② 视觉强的站，条目信息反而更密。** 越是好看的（belentenorio、elenamiska、zefs），每个条目携带的信息越多（客户/角色/平台/年份/一句说明）。**图和信息不是此消彼长。** 单调的原因是条目信息太少，不是图太少。

**③ 「最近在做什么」比「作品集」更能让站活着。** nathansmith 的动态流、zefs 的 `'19—now`、calebbarclay 的迭代日志——三种不同做法，同一个目的。作品集会过期，动态不会。
