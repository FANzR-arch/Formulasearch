# 多平台个人网站补充调研

> 更新：2026-08-07  
> 来源：Exa、X、Reddit、小红书、B站，以及相关实站。  
> 用途：验证 [`10_个人网站演示参考.md`](10_个人网站演示参考.md) 的方向，并补充中文建筑作品集、真实访客反馈和可维护性证据。

## 结论先行

这轮没有推翻上一轮的主方向，但修正了四件事：

1. **Editorial Archive 仍然应是第一套演示。** Corentin 的网格与档案系统依然最完整。
2. **Personal Project Platform 不应该做成后台。** 首页可以出现一小块“可触摸资产桌面”，但完整内容仍由清晰索引承担。
3. **建筑作品不能把 PDF 原样搬上网页。** 需要重新设计项目顺序、黑白与彩色切换、横向浏览和项目间导航。
4. **“用 AI 做个人网站”已经不是差异点。** 中文平台充斥 1–2 小时建站、Codex 建站和套模板教程；识别度只能来自真实内容、稳定结构和一致的视觉母题。

## 1. 新增的高价值演示参考

### A. Hal Lee：可触摸的个人资产桌面

- 来源：[X 演示视频](https://x.com/i/status/2083196877714112560)
- 观察到的界面：深绿色桌面上摆放 About Me、Career Card、Highlighted Projects、Side Projects 等纸张和文件夹。
- 物件可以拉近查看、翻页、撕开贴纸；交互不是覆盖在卡片上的装饰，而是“查看内容”的动作。

值得迁移：

- 把不同资产做成具有明确身份的对象，而不是同一种圆角卡片。
- 点击先让对象靠近、聚焦，理解后再进入完整详情。
- 纸张、文件夹、标签和印章可以表达“个人档案”，但只用于首页精选区或关于页。

不要迁移：

- 不把整站做成桌面寻宝游戏。
- 导航、搜索、移动端和无动画模式仍需要普通网页结构。

对演示的影响：在 Personal Project Platform 方案中增加一块 **Tactile Asset Desk**，只承载 4–6 个精选入口。

### B. Vamsi Batchu：阅读和重排成为同一动作

- 来源：[X 演示视频](https://x.com/i/status/2085183154185195666)
- 观察到的界面：多栏文章围绕 SVG 和可拖动图片排布；拖动视觉素材时，文字仍然保持阅读关系。

值得迁移：

- 写作页可以允许图片进入正文网格，而不是永远位于段落上方。
- 一篇视觉型文章可以有少量可移动素材，表达“思考过程仍可重新组合”。

不要迁移：

- 长文正文不能全部依赖自由拖拽。
- 移动端回到稳定的单栏阅读，不强行保留桌面实验。

对演示的影响：它是 **视觉文章模板** 的参考，不是首页信息架构参考。

### C. TAO 建筑作品集：把 PDF 重新编译成网页

- 来源：小红书笔记《尝试用 Codex 做的个人建筑作品集网站》，作者“米理混子（征战意大利版）”，2026-06-03，笔记 ID `6a2021f3000000003601a014`。
- 作者先在 InDesign 画网页原型，确定比例、留白、标题与图片关系。
- 首页只保留身份；项目列表维持黑白灰，进入详情后图片恢复彩色。
- PDF 的固定项目顺序被改成横向项目卡片；项目之间可以连续切换。
- 当前标题缩小为上方导航，下一项目标题从下方放大进入，并用轻微吸附避免停在半过渡状态。

这是本轮和 Formulasearch 最直接相关的中文案例，因为它同时涉及建筑背景、个人作品、摄影与其他内容。

值得迁移：

- 建筑作品先在静态排版工具里确定比例与图文关系，再进入代码。
- 列表页克制，详情页恢复材料、图纸和照片的颜色。
- 项目切换要保留“当前项目 / 下一项目”的方向感。

不要迁移：

- 首页不能只剩名字和职业。Formulasearch 还有 Skills、工具、写作和业务入口。
- 横向浏览仅用于建筑或摄影项目，不扩散到全站。

### D. JIEJOE：每个内容区都有自己的交互隐喻

- 来源：[B站《拿了个国际小奖，我的个人网站演示》](https://www.bilibili.com/video/BV1hYceeGEuq)
- 实站：[jiejoe.com](https://www.jiejoe.com/)
- 视频、平面设计、技能、联系和图库分别使用胶片、扑克牌、软件界面、电话线、无限画廊等交互隐喻。
- 图库选中图片后移动到中央并显示名称与日期；其他图片淡出。

值得迁移：

- 内容类型可以拥有不同展示方式，但字体、颜色、反馈速度与导航要统一。
- 选中一个内容时让其他内容降权，适合项目列表和作品图库。
- 联系动作可以直接完成，例如复制邮箱，而不是只显示图标。

不要迁移：

- 加载动画、光球、X 光扫描、物理灯泡、眼球跟随、胶片、扑克牌、无限画廊不能全部堆进 Formulasearch。
- 每页只选一个与内容有关的交互母题。

### E. Garry：网站同时承载作品、文章和联系

- 来源：[B站《耗时 3 个月，为了找工作，我做了一个网站当简历》](https://www.bilibili.com/video/BV1sq4y1j74A)
- 内容分为个人简介、作品、文章和联系，而不是只有项目画廊。
- 悬浮某张作品卡时，其他卡片半透明，帮助聚焦。
- 邮箱和联系方式支持点击复制，明确照顾 HR 和合作方的任务。

它同时暴露了两个长期维护问题：

- 视频发布时移动端仍未完成。
- 外部作品记录删除后，站内卡片没有及时同步，出现空条目。

对 Formulasearch 的影响：移动端不能排到桌面版完成以后；外链资产需要状态字段和定期失效检查。

### F. R—K ’26：不同页面共享系统，不共享同一种版式

- 制作拆解：[R—K ’26: The Thinking and Code Behind a Portfolio Led by Presence](https://tympanus.net/codrops/2026/04/07/r-k-26-the-thinking-and-code-behind-a-portfolio-led-by-presence/)
- 全站使用 12 栏网格；首页保持清晰，项目页强调呈现，Insights 更像杂志跨页。
- 页面有关联，但不重复同一种卡片和同一种密度。
- 声音默认关闭，由访客主动开启。

对 Formulasearch 的影响：五个栏目共享 token、网格和运动节奏，但货架、写作、作品不应该长成同一个模板。

### G. ISA Archive：长期扩展先设计内容结构

- 项目说明：[ISA Archive](https://yoonjonglyu.github.io/work/isa-archive/)
- 它把个人站当作 UI 架构练习：简历、作品与档案从结构化数据生成，组件先于页面设计。

对 Formulasearch 的影响：条目模型与组件契约要先于页面特效，否则内容从 20 项扩展到 200 项时会被迫重做。

## 2. 社区反馈形成的约束

### Reddit：强视觉不是问题，阻碍浏览才是问题

两条讨论提供了相对稳定的使用反馈：

- [Where do you find actually good website design inspiration?](https://www.reddit.com/r/web_design/comments/1ko8f6i/where_do_you_find_actually_good_website_design/)：帖子认为 Awwwards 常常过度实验、实际不可用；高赞回答更愿意看真实行业网站、竞品和已经上线的具体案例。
- [Thoughts on “artistic” websites?](https://www.reddit.com/r/web_design/comments/4gsgjo/thoughts_on_artistic_websites/)：用户反感劫持滚动、难找导航和每次操作都出现加载层；作品应该尽早出现。

这不是“不要创意”，而是给创意设定完成条件：

- 首屏可见身份、入口和至少一个真实内容。
- 不劫持滚轮，不强迫看完片头。
- 页面去掉动效后仍能导航和阅读。
- 参考真实上线站解决结构，获奖站只解决局部视觉和交互。

### X：小交互比大场面更容易形成记忆

本轮较有价值的 X 演示都不是再加一个全屏 WebGL，而是把一个普通动作做得具体：翻开、撕开、拖动、重排、聚焦、复制。

对 Formulasearch 的约束：先为“拿走一个 Skill”“展开一条记录”“预览一个作品”“复制一个入口”设计反馈，再考虑环境特效。

### 小红书：AI 建站本身已经同质化

搜索结果大量集中在：Codex 制作、1–2 小时速成、零代码、Vibe Coding 和现成动效资源。另一个高互动笔记《0 代码做个人网站 2.0：别再做成 AI 模板了》给出的流程仍然是：

1. 整理内容。
2. 找具体参考，不让 AI 自由发挥。
3. 选择组件和设计方法。
4. 最后增加少量动效与响应式处理。

这是对当前 Formulasearch 流程的验证，不是新的视觉方案。

### B站：适合研究“怎么演示”，不适合直接决定信息架构

B站高热度内容主要是个人站演示、交互拆解和搭建教程。视频能清楚呈现滚动节奏、鼠标反馈和页面转场，但标题和播放数据不能证明网站长期好用。

使用方式：从视频拿动效时序，从实站和真实内容拿结构。

## 3. 修订后的三套演示

### 演示 1：Editorial Archive，优先级最高

保留上一轮方案，增加建筑作品专用浏览：

- 首页：身份、五入口、精选 4 项。
- 货架：List / Overview 双视图。
- 建筑项目：黑白目录进入彩色详情，横向项目切换，当前与下一项目标题连续变形。
- 写作：稳定三栏或两栏阅读，不使用自由拖拽。

### 演示 2：Tactile Asset Platform

把原 Personal Project Platform 进一步具体化：

- 首屏下方放一块资产桌面，只出现 4–6 个精选对象。
- 对象对应 Skill、工具、文章、作品或正在构建的项目。
- 点击先靠近并露出摘要，再进入标准详情页。
- 完整货架仍是可搜索、可筛选、可复制链接的普通索引。

这套借 Hal Lee 的物件关系，不借操作系统仿真。

### 演示 3：Layered Visual Hub，降为探索项

- 保留强视觉首屏、悬浮多图预览和精选/档案分层。
- 删除加载片头、声音许可和多重教学提示。
- 每页只允许一个核心动效母题。

它只有在前两套显得过于理性时才需要继续。

## 4. 下一步的明确输入

开始画演示前，需要从真实资产里固定：

- 3 个视觉 Skill。
- 1 个其他 Skill 或工具。
- 1 篇视觉型文章。
- 1 个建筑项目。
- 1 个 AI 视觉作品。
- 1 个业务或伙伴站入口。

三套演示必须共用这 8 项内容。没有这批内容，继续研究视觉只会重新回到“换 moodboard、换卡片、换动效”。

## 5. 证据边界

- Exa 用于发现实站、制作拆解和结构型项目。
- X 用于观察近期正在构建的交互原型；互动量只表示传播，不等于可用性证明。
- Reddit 用于补充真实访客和开发者反馈；帖子与评论是社区意见，不是定量用户研究。
- 小红书用于观察中文个人站的内容趋势，并打开两篇相关笔记核对正文。
- B站用于核对完整演示时序和作者讲解；本轮读取了视频元信息与字幕。
- 以上平台均已通过本机 OpenCLI 或 Exa MCP 实际调用，不再使用“后端不可用”的旧判断。
