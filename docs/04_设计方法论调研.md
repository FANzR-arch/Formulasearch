## 0. 一句话结论

**个人网站的失败不是审美失败，是架构失败。** 调研里所有讲得深的人，都把"怎么设计"这个问题
往前推了两步——先定**它服务谁、要它干什么**，再定**内容之间的关系**，最后才轮到版式和视觉。
顺序反了的站，launch day 好看，180 天后死掉。

对应到你：`00_网站规划.md` 已经做完第一步（定位/板块/SEO 策略），
**第二步「内容模型」是当前最大的空缺**，第三步「视觉调子」反而不是最急的。

---

## 1. 四层决策顺序（调研得出的共识骨架）

多个独立来源殊途同归，收敛成同一个顺序：

```
① 目的层   这个站要为谁完成什么任务？成功长什么样？        ← 你已完成 80%
② 结构层   有哪些"实体"、它们怎么互相关联、谁生成谁？      ← 你的空缺
③ 界面层   每类页面的任务是什么？密度、导航、层级          ← 部分在规划里
④ 表层     字体、色彩、网格、动效                          ← 你目前停在这层纠结
```

> 关键论点（Blazej Mrozinski, *Building a Personal Website Like a Product*）：
> 开发者的默认心智是"我需要哪些页面"，产品的心智是"存在哪些实体、它们怎么关联、
> 哪些视图服务哪些人"。**前者产出宣传册，后者产出系统。**

## 2. 五个可直接拿来用的框架

### 框架 A｜内容模型先于版式（最适合你的一个）

**来源**：[Building a Personal Website Like a Product](https://www.blazejmrozinski.com/blog/personal-site-as-product/)（2026-03，Astro + Tailwind + Netlify，作者不写代码，5 天 70 commits）

核心做法：动手前先写一份**更像数据库 schema 而不是线框图**的规格文档，定义：

- 有哪些内容类型（Person / Company / Project / Publication / BlogPost…）
- 每类有哪些**必填字段**（schema 在 build 时校验，缺字段直接构建失败）
- 类型之间的**显式关联**（Project 必须挂到某个 Company；BlogPost 可引用 Project）

带来的三个连锁收益，都不是"设计"能给的：

1. **一处修改，全站一致**——新增一个作品，产品页自动生成、公司页自动列出、首页自动更新
2. **结构化数据是白送的**——JSON-LD 从内容模型自动派生，不是另开一条维护线
3. **发布摩擦趋近于零**——封面图在构建管线里生成，而不是"发文章还得先开设计工具"

> 他的判断：**大多数个人网站是为 launch day 设计的，产品思维是为 day 180 设计的。**

**对你的直接映射**（你的实体比他还复杂）：

| 实体 | 关键字段 | 关联 |
|---|---|---|
| Person | 简介、称谓、双语 | → 全部 |
| Service（业务线） | 面向谁、交付物、流程、FAQ | → Case、Work |
| Work（AI 产品 / 建筑作品） | 类型、时间、状态、技术栈 | → BlogPost、Skill |
| Case（交付案例） | 客户、问题、做法、结果、授权状态 | → Service、Work |
| Skill | 用途、开源地址 | → Work、BlogPost |
| BlogPost | 分类、标签、双语配对 | → 任意实体 |
| Course | 平台、状态、外链 | → Skill |

这张表一旦定死，`00_网站规划.md` 里那个 `Person + Organization + Product + Article + Course + Service + FAQPage` 的 schema 清单就不再是"上线前要记得补的 SEO 任务"，而是**自动产物**。

### 框架 B｜把自己的站当客户项目做（和你双身份定位同构）

**来源**：[How I Built k8mak.com: Product Strategy for a Personal Site](https://www.k8mak.com/blog/how-i-built-k8mak/)（2026-05）

作者把服务 $2.7B 客户的 15 步产品策略流程原样跑在自己站上。她说四步真正改变了决策：

**① JTBD / 人格化受众**——她给最重要的那个受众起名叫 Hannah（正在评估要不要面试她的产品 VP）。
就这一个人格，把作品集案例从"营销附属品"提到了**全站最高优先级内容**。

> 迁移到你身上：你的站有两类人——**要验货的潜在客户**、**来读东西的同行/读者**。
> 给他们各起个名字，写清楚"他落地后 30 秒内要看到什么才不走"。
> 你现在的规划里这两类人是抽象的，没有具体到能用来砍需求。

**② 北极星指标**——她定了一个数：Monthly Qualified Engagements（案例深读 + 工具完成 + 博客互动 + 表单 + 购买合成一个数）。
一个数判断站有没有在干活。

**③ RICE 打分**——结果反直觉：About 页那三段"为什么我的跨领域经历是优势而不是不专注"的文字，
RICE 打了 5000 分，**高于几乎所有耗时十倍的功能**。规律是：高影响低成本的**内容工作**持续碾压新功能。

> 这条对你尤其重要：你有建筑 → AI 的跨界叙事，
> 和她那个"Why Breadth"是同一类问题。它值得被当成一个**独立的高优先级内容模块**来做，
> 而不是塞在 About 页里的一段个人故事。

**④ Pre-mortem（事前验尸）**——写一行代码前先假设"三个月后这站失败了，为什么"。
她列出的风险里有一条你也躲不掉：**双流策略会不会其实是两个策略披着一件风衣**。
她的判断是重叠是真实的（同一篇文章既拿 SEO 又证明思考能力），但把它标为最大战略风险。

被 RICE 和 pre-mortem 砍掉的东西：客户证言轮播（改为嵌进案例正文，更可信）、
定价计算器（需要算价的人还没准备好买）、三个付费产品砍到一个、
交互式简历时间线（招聘方就是要 PDF，过度设计不增加说服力）。

### 框架 C｜一人公司站的结构共识（收敛，不是扩张）

**来源**：[Consultant Website Strategy Guide](https://www.sitesgo.com/blog/consultant-website-strategy)、[One Page or Twelve?](https://blog.autom84you.com/post/consultant-personal-brand-site-one-page-or-twelve)

几条反复出现、且和你现有规划**有张力**的判断：

- **最常见的错误是「以服务清单开场」。** 服务是你做什么，洞察是别人凭什么信你能做。
  **先给思考，再给菜单。**
- **用"客户拿到什么"命名服务，而不是"我花什么时间"。**
  "六个月市场进入策略，从问题界定到可上董事会的方案"是可购买的结果；"策略咨询 retainer"是时间承诺。
- **明确写出你不服务谁。** "我们服务各类组织"是全站最贵的一句话——它吸引错的客户、
  浪费沟通、稀释定价权。
- **诚实用"我"而不是"我们"。** 客户签约后发现"我们"= 一个人 + 两个外包，信任在合作开始前就没了。
- **只有一个板块需要持续更新（写作/洞察），其余页面应该 12 个月不动。**
  典型死法是建了个"动态/News"栏目，然后被客户活淹没后弃更。
- **站的唯一工作**：让一个已经有兴趣的人走出下一步。一个明确 CTA，不是三个。

> ⚠️ 和你的张力：你规划了 7 个板块。上面几家的经验值是**3–5 页**。
> 这不意味着你要砍——你的站确实要装的东西比一般咨询师多（作品 + Skills + 博客 + 课程）。
> 但值得问一句：**这 7 个板块里，有几个是"客户导向"的，有几个是"读者导向"的，
> 它们要不要在导航上就分成两条路？**（见第 4 节）

### 框架 D｜反模板：具体到 token 级

**来源**：[Why Every Design Portfolio Looks the Same](https://thecrit.co/resources/why-every-portfolio-looks-the-same)、[Why 90% of Developer Portfolios Look the Same](https://parthh.in/blogs/why-90-percent-of-developer-portfolios-look-the-same)、[How to Make Your AI-Generated Website Look Like You Built It](https://sailop.com/blog/how-to-make-ai-website-look-unique)

**为什么现在的站长得都一样**（三个独立来源共识）：模板成了起点 + AI 工具把基线抬高但天花板压平 +
求职焦虑导致人人选"不会错"的选项。结果是"不冒犯任何人也不让任何人兴奋"。

**技术层面最可操作的一份清单**（Sailop 那篇，直接可查你自己的稿）：

| 维度 | AI 默认（=模板味） | 破法 |
|---|---|---|
| 字体 | Inter / Roboto / Poppins / Montserrat / Geist，单字族两个字重 | **两个不同类别配对**：一个 display（衬线/压缩体）+ 一个 body（中性无衬线） |
| 主色 | 蓝紫区间（hue 190–290），Tailwind 默认蓝 | 选 hue 0–180 或 290–360，例：深玫瑰 `hsl(347,72%,48%)`、燋橙 `hsl(22,…)` |
| 底色 | 纯 `#fff` / `#000` / `zinc-950` | 暖白 `hsl(35,20%,96%)` 或带色偏的深色——**读起来像选择，不像 fallback** |
| 版式 | 等分三栏卡片 | 非对称比例（5fr/3fr、7fr/4fr）。等分三卡最伤转化：眼睛先读到"填充物" |
| 间距 | 全站一个 gap 值 | **段间宽、段内紧**——密度和留白的对比才被读成节奏 |

**内容层面**（另两篇的共识，比视觉更重要）：

- 最有力的作品集是**内容重**而不是**设计重**。3 个带完整案例的项目 > 10 个只有 README 链接的项目
- 案例别再用 problem-process-solution 那套——招聘方能预测每一屏。改成**只有你能写出来的结构**
- **狠心策展**：最好的 3–5 个项目、最强的 6–8 项技能。列全等于稀释
- 差异化现在来自**思考的证据**（写作、字体选择、版式判断、404 页的文案），不来自界面精致度——精致已是入场券

### 框架 E｜艺术指导先于设计（定调子这一步到底在定什么）

**来源**：[Web art direction: the strategic layer behind every memorable website](https://metabole.studio/en/blog/web-art-direction)（2026-04）

一句话区分：**网页设计负责执行，艺术指导负责决定。**
设计师做出好看的按钮；艺术指导解释这个按钮为什么是这个形状、颜色、位置，它怎么连回品牌定位。

它明确反对把"定调子"做成 moodboard 会：

> "现代、专业"这种简报等于什么都没说。艺术指导是一个**结构化流程**，不是一次情绪板会议。

三阶段：

1. **框定**——定位是什么？受众是谁？**竞品/同类站的视觉套路是什么？**
   目标不是讨好所有人，是找到真正能区隔的那个视觉角度
2. **创意立场**——moodboard、字体探索、色板、版式原则、图像处理。
   每个决定都要能论证，连回定位。这不是造型练习，是**把策略翻译成视觉**
3. **落地**——所有页面在已定义的视觉系统内成形，UX 在这一步嵌入

关键提醒：**艺术指导必须在第一个像素之前定义，不能后贴。** 越早进流程，后期返工越少。

> 对你：你已经选了"瑞士国际主义"，但那是**风格标签**不是**创意立场**。
> 差的那一步是：为什么是瑞士？它翻译的是你的什么定位？
> 一个可用的论证链条是——「建筑训练出身 + 做 SEO/GEO 这种讲究结构和可检索性的活」
> → 网格、层级、克制、信息优先 → 瑞士。这条链能说通，调子才立得住，
> 而不是"因为好看"。（`03_参考去哪找.md` 结尾提的"瑞士骨架 + 档案馆密度"融合方案，正是一个创意立场雏形。）

## 3. 交叉验证出的高置信度结论

多个独立来源同时说的，可信度最高：

1. **上线速度 > 打磨程度。**「有真内容和能用工具的站，赢过有占位文字的漂亮站。」
   作品集没发布的每一周，都是目标受众找不到你的一周
2. **写作是最高杠杆的板块。** 咨询站、作品集站、个人站三类来源都指向同一处：
   持续的原创思考既是 SEO 引擎、又是能力证明、又是信任构建，一份工作干三件事
3. **两类用户，不是一类。** 人类访客和搜索/AI 引擎是**两个用户类型，各有各的 UI**——
   人的 UI 是版式，机器的 UI 是结构化数据。只优化前者是宣传册思维
4. **维护成本要在设计阶段就设计掉。** 任何"发布时还要手动做一步"的环节，
   最终都会变成你停更的理由
5. **可讨论性**：调研里出现了一个反向声音（小红书高赞《没人在乎网站了，别浪费时间搭建个人网站》）。
   它对**纯展示型个人站**大致成立。对你不成立的理由很具体：
   你的站是"网站搭建"这条业务线的样品，客户点进来是在验货——站本身就是交付物

## 4. 需要你自己拍板的三个决断（调研给不出答案）

**① 双身份在导航上分不分岔？**
k8mak 的双流模型是"共用基建、不分导航、用同一个北极星指标兜底"。
你的规划是 7 个板块平铺。第三种可能是首页做一次显式分流（"你是来找我做事的" / "你是来读东西的"）。
三条路各有代价，但这个决定会反向决定首页和信息架构，得先定。

**② 7 个板块要不要收敛？**
一人公司站的经验值是 3–5 页，你有 7 个。不一定要砍板块，但可以砍**导航层级**——
比如 Skills / 课程 收进作品或关于页的次级入口。判断标准用 RICE：哪个板块真的推动"合格互动"？

**③ 瑞士国际主义的论证链条**
风格标签不等于创意立场。把"为什么是瑞士"写成一句能对客户讲的话，
调子才算定完；否则参考收得再多，最后还是凭手感挑。
