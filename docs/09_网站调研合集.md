> 更新：2026-08-07  
> 用途：把历史对话、`docs/00–08`、Typewolf Top 40 扫描和 `refs/images/` 素材整理成一个当前入口。  
> 状态：**研究与规划合集。视觉定稿和开发规格尚未开始。**

---

## 先看结论

Formulasearch 的定位是：

> **一张能在 30 秒内说明身份的个人名片，外加一座不断增长、别人可以拿走东西的个人资产货架。**

全站用这句话串联不同资产：

> **我做过的每件事，都尽量变成别人可以直接拿走使用的东西。**

这个叙事能够同时容纳视觉 Skills、提示词与审美分享、工具、写作、作品、课程和业务。长期工作记录也反复出现同一种做法：完成实践，再把过程整理成 Skill、模板、SOP、工具或文章。

当前整体视觉方向可以概括为：

> **瑞士式骨架 + 档案式密度 + 编辑型大图。**

- 瑞士式骨架负责网格、层级、对齐、专业感。
- 档案式密度负责容纳不断增长的内容、编号、标签和检索。
- 编辑型大图负责体现视觉能力，避免纯文字档案站过于传统和单调。
- 动效只服务于进入、预览、状态变化和空间关系，不把每一个区域都做成表演。

## 1. 网站到底为谁、做什么

### 访客

- 读者：来看 AI 实践、提示词拆解、工具教程和个人思考。
- 潜在客户：验证网站搭建、SEO/GEO 和视觉表达能力。
- 招聘或合作方：快速判断身份、经历、作品和可信数据。

### 30 秒内必须讲清的事

1. 你是谁：建筑背景，正在做 AI 视觉、工具、内容与网站实践。
2. 你长期在做什么：把实践沉淀成能安装、下载、阅读或直接使用的资产。
3. 从哪里进入：货架、写作、作品、业务、关于。

### 网站的第一目标

网站首先承担**名片 + 沉淀地**的作用。询盘转化只是其中一个结果，首页无需套用销售漏斗。

SEO/GEO 继续约束技术和内容架构，但不指挥全部选题。页面要可索引、可引用、可独立分享，正文要落在自己的域名上，结构化数据和站内关联要随内容模型生成。

## 2. 当前建议的信息架构

### 一级导航：五项

| 入口 | 放什么 | 访客动作 | 展示方式 |
|---|---|---|---|
| **货架** | 审美分享、视觉 Skills、其他 Skills、工具 | 安装、下载、复制、在线使用 | 图像主导 + 可筛选目录 |
| **写作** | AI 实践、方法、教程、个人思考 | 阅读、收藏、继续探索 | 长文阅读 + 分类索引 |
| **作品** | 建筑、AI 视觉、摄影（待定） | 快速浏览、查看细节 | 大图、轻文字、快速加载 |
| **业务** | 网站搭建、SEO/GEO | 明白目前能提供什么 | 一屏说完 + 真实链接 |
| **关于** | 身份、经历、数据、联系方式、社交入口 | 判断可信度并联系 | 事实化名片 |

课程不占一级导航，从相关位置外链：SEO 课从业务/写作进入，PA 课从作品或关于进入。

### 首页只承担入口任务

首页只做四件事：

1. 用一行身份和一句主张讲清你是谁。
2. 给出五个入口。
3. 露出少量最新或最重要的内容，证明网站仍在生长。
4. 让人可以立刻进入某个具体条目，自我介绍保持简短。

首页可借 Dinamo 的「顶部文字目录 + 下方视觉区块」。内容顺序按照 Formulasearch 的访客任务重新安排。

### 三种内容不能共用一种卡片

| 内容任务 | 典型内容 | 应有结构 |
|---|---|---|
| 拿走就用 | Skill、提示词、工具 | 样例图、适用场景、使用方式、拿走按钮 |
| 坐下来读 | 长文、教程、思考 | 标题、摘要、正文、目录、关联内容 |
| 扫一眼看 | 建筑、AI 视觉、摄影 | 大图、项目名、类型/年份、极短说明 |

卡片应复用信息结构和设计 token。三类内容分别使用适合自己的形态，避免全站套用「上图下文圆角卡」。

## 3. 内容资产的真实规模

以 2026-08-06 的扫描为准：

- 19 套视觉 Skill，另有中文排版共享规范。
- Numerologist_skills 当时为 916★，是最硬的外部验证之一。
- 视觉 Skill 公开仓库当时为 60★。
- 9 个左右可直接上的工具，另有若干待加工项目。
- 41 篇已发布长文，30+ 个进行中长文文件夹；与旧站 26 张文章卡存在重叠，尚未完成去重。
- 建筑作品、AI 视觉和摄影素材足以形成作品区。
- 网站搭建有水土营造、WaterSystem 两个伙伴站可直接外链。
- SEO/GEO 不展示 Lucius 合作细节，以教程课件和脱敏工作流方法为证明。

当前要解决四个问题：

- 怎样分组才不乱；
- 每个条目出现多少信息；
- 如何让 Skill、配对文章和示例图互相导流；
- 如何降低长期更新成本。

### Skill 与文章的关系已经可以定下来

两者承担不同任务，保留独立页面：

```text
Skill  = 拿走就用
文章   = 看懂为什么
```

Skill 保持独立货架，以图和使用入口为主；配对文章留在写作区，Skill 页底部链接完整拆解。文章页也可反向链接对应 Skill。

## 4. X、GitHub 与外部站的角色

### X

> **X 是发生地，网站是沉淀地。**

- 不镜像时间流，不嵌整页推文。
- 页脚或关于页保留简单入口。
- 单个资产页可以标「来自哪一期审美分享 / 查看原帖」。
- 粉丝数等会过期的数据只放一处；展示时用更新时间或近似值。

### GitHub

GitHub 是安装、源码和 star 的外部证明，但不该继续承担全部落地页职责。X 上已经产生的点击目前大量流向 GitHub；新站应先用自己的页面解释「这是什么、适合谁、怎么拿走」，再把安装或源码动作交给 GitHub。

### 课程与伙伴站

主站负责叙事和入口，课件、工具、伙伴网站可继续独立部署。主站先讲清上下文，再把访客送到外部站。

### 扫描得到的三条共识

1. 44 个参考站里没有独立封面页，首页就是入口。
2. 视觉越强的站，单个条目携带的信息往往越完整。图片和信息密度可以同时保留。
3. 「最近在做什么」比静态作品集更能让网站保持活性。

## 7. 视觉和动效应如何收敛

### 建议保留的视觉原则

- 图片权重大于长段说明，但不能牺牲条目信息。
- 首页和业务页用清晰网格，货架和索引用较高密度。
- 暖白或中性底色、近黑文字、一个高饱和信号色；避免默认蓝紫科技渐变。
- 标题可使用有性格的 display 字体，正文使用稳定易读的中文字体。
- 圆角、阴影和材质都要有统一规则，不使用默认 SaaS 卡片风。
- 不同页面可以有不同密度，但必须共享字体、颜色、线条、间距和运动节奏。

### 动效只回答三个问题

1. 我现在进入了哪个层级？
2. 鼠标或手指当前指向什么？
3. 页面内容之间是什么关系？

适合保留：区块进入、悬浮预览、轻微图像位移、筛选状态、页面转场、`prefers-reduced-motion` 降级。

不建议同时叠加：全屏光栅、3D 倾斜、鼠标追踪、自动轮播、悬浮弹图和大量视差。单个效果好看不等于它们叠在一起还能读。

## 8. 对话里出现过、但不能当成当前定稿的方案

| 方案 | 当前判断 |
|---|---|
| 「Expression is all you need」独立封面 | 是一次创意探索，不是已定首页文案；与 44 个参考站「首页即入口」的证据冲突 |
| 点击封面后进入主页 | 尚未拍板；会多一次阻挡，尤其不利于从 X/搜索直达具体内容 |
| 全站做 22 张图卡的图墙 | 原型已被明确否掉；「图片 > 文字」偏好保留，但图墙实现不保留 |
| 所有板块原地筛选、不跳页 | 属于被否掉原型的一部分，不能视为当前导航决策 |
| 全站纯档案馆式 | 信息结构有用，但用户已明确觉得纯文字个人站太传统、太单调 |
| 七个板块平铺 | 已被五项导航替代；课程改为外链，案例合入作品/业务证明 |
| 长篇业务页、价格、流程、case study | 已否定；业务一屏说完，伙伴站直接挂链接，SEO/GEO 用教程与脱敏方法论证明 |
| 把 X 内容流搬进网站 | 已否定；只保留入口和个别原帖来源 |

### 关于独立封面的建议

当前证据更支持：**不要做必须点击才能进入的独立封面。**

如果仍想保留轮播、视频、Logo 和金句，可以把它们做成首页第一块内容；导航和向下进入内容的路径从第一屏就可见。这样既保留表达性，也不会挡住从搜索、X 或外链进入的人。

## 10. 接下来怎么继续

当前不应继续无边界地搜参考，也不应直接开发。按已经确认的顺序推进：

1. **冻结条目表**：从 `01_内容清单.md` 选出首发条目，并补齐一句话、图、状态、拿走方式。
2. **画 3–5 种条目结构**：图主导、图文、纯文字、数据型；任意首发条目都能落进去。
3. **按条目自然分组**：用真实分组验证五导航，必要时调整名称或层级。
4. **画页面框图**：首页、货架、写作、作品、业务、关于、单资产页、文章页。
5. **画跳转图**：特别检查从 X/搜索进入单条内容、相邻内容继续浏览、三步内回首页。
6. **才开始定调子**：把 Dinamo、Cloudflare、四段录屏和五张编辑图转成可写进 CSS 的参数。
7. **开发**：技术栈再确认；Astro 仍是当前倾向，但尚未最终拍板。

### 动工前仍需拍板

- 全站双语，还是只做业务/关于英文版。
- 摄影是否进入首发导航。
- 货架先做一页三区，还是一开始就拆成独立二级页。
- `image-prompt-skills` 与 `Phil-design-skills` 的对外统一名称。
- 首页第一句话最终使用身份描述、资产主张，还是两者组合。
- X/GitHub 等会变化的数据是自动同步、手工更新，还是统一使用近似值。
