# 周全作品集站：可复用部分拆解

> 更新：2026-08-08  
> 来源：[周全作品集 Mason Chou Portfolio](https://zhouquan.framer.website/)  
> 用途：只提取可迁移到 Formulasearch 的布局与交互，不把原站当作整站模板。  
> 可运行示例：[`refs/structures/zhouquan-focus-grid/index.html`](../refs/structures/zhouquan-focus-grid/index.html)

## 结论

这个参考站最有价值的不是黑色，也不是超大字，而是它把视觉型内容变成了一个可以快速扫过的索引：

1. 首屏先建立身份和气质。
2. 作品使用不对称网格，避免每项都长成同一种卡片。
3. 悬浮某项时，其他内容降权，当前内容出现明确的进入提示。
4. 详情页先给项目事实，再连续展示大图和视频。

这些手法适合 Formulasearch 的**首页精选区和作品页**，不适合货架、写作和全站导航。

---

## 1. 首屏：视觉身份和事实同时出现

### 原站有效的关系

```text
超大姓名 / 字标                    视觉符号或人物

小型元信息栏：作品集 / 名称 / 职位

人物或主视觉          7 年经验 + 能力范围 + 联系入口

能力标签横条：品牌视觉 / 三维 CG / 壁纸与锁屏
```

强项是**视觉冲击和事实没有分开**。访客不是先看一张海报，再向下找这个人做什么；身份、经验和能力仍在第一段出现。

### 迁移到 Formulasearch

首页第一屏可保留三个层级：

```text
FORMULASEARCH / PHIL

一句真实身份说明
审美、AI、内容与工具，被整理成可以直接拿走的资产。

货架 / 写作 / 作品 / 业务 / 关于
```

主视觉可以占 40%-55% 宽度，但五个入口必须同屏可见。不要增加必须看完的片头、滚动劫持或自动播放声音。

---

## 2. 不对称作品网格

### 要提取的不是 Masonry，而是“主次”

原站让一张主图占据更大面积，旁边用较小作品建立节奏。这样访客自然先看精选项目，再扫其他项目，不需要额外写“重点推荐”。

Formulasearch 建议使用 12 栏网格：

| 位置 | 栏宽 | 角色 | 建议内容 |
|---|---:|---|---|
| A | 7 栏 | 本屏主项 | 视觉 Skill 或代表作品 |
| B | 5 栏 | 次重点 | 工具或 AI 视觉项目 |
| C | 5 栏 | 次重点 | 建筑 / 摄影项目 |
| D | 7 栏 | 横向收尾 | 业务入口或系列集合 |

必须保留的元信息：

```text
项目名
内容类型 / 角色
年份或状态
```

不要只放图片和编号。Formulasearch 的内容类型比纯作品集复杂，访客需要在点击前分辨这是 Skill、文章、工具还是作品。

---

## 3. 悬浮聚焦交互

### 桌面端行为

当指针或键盘焦点进入一个条目：

1. 当前条目保持 100% 不透明度。
2. 同组其他条目降至 24%-36%。
3. 当前图片中央出现一条细线和 `VIEW / 查看`。
4. 图片轻微放大 1.015-1.03 倍；不要大幅缩放。
5. 交互结束后恢复，不改变滚动位置。

### 时序

| 属性 | 建议值 |
|---|---|
| 其他条目降权 | 180ms ease-out |
| 当前图片放大 | 240ms cubic-bezier(.2,.8,.2,1) |
| 指示线展开 | 220ms cubic-bezier(.2,.8,.2,1) |
| 文字出现 | 指示线开始后 40ms |

### 可访问性和移动端

- `:hover` 和 `:focus-visible` 必须获得同样反馈。
- 每个条目使用真实 `<a>`，不能用只有点击事件的 `<div>`。
- 移动端不做“其他条目淡出”，直接显示标题、类型和进入箭头。
- `prefers-reduced-motion: reduce` 下取消缩放和指示线动画。

## 4. 项目详情页开场

原站的有效骨架是：

```text
超大项目标题
--------------------------------
项目说明 / 职责          项目首图
Category                 大图或视频
Client                   大图或视频
Duration
Location
```

迁移时把左侧事实改为 Formulasearch 需要的字段：

| 字段 | 说明 |
|---|---|
| 类型 | Skill / 工具 / 文章 / 建筑 / AI 视觉 / 网站 |
| 我的角色 | 设计、开发、研究、内容、视觉指导等 |
| 时间 | 年月或版本 |
| 状态 | 可使用 / 持续更新 / 已归档 |
| 入口 | 安装、复制、阅读、访问项目 |

视觉作品可以继续用连续大图；Skill 和工具详情不能照搬画册结构，必须优先出现“适用场景”“使用方式”和真实入口。

## 5. 可直接采用的视觉规格

以下不是对原站像素级复制，而是适合 Formulasearch 的安全起点：

```css
:root {
  --page: #050505;
  --ink: #f4f4ef;
  --muted: #9b9b94;
  --line: rgba(244, 244, 239, 0.22);
  --gutter: clamp(18px, 3vw, 52px);
  --display: clamp(64px, 12vw, 210px);
  --title: clamp(28px, 4vw, 68px);
  --meta: clamp(11px, 0.8vw, 14px);
}
```

布局规则：

- 内容最大宽度不锁死在传统 `1200px`，桌面端允许接近全宽。
- 左右边距使用 `clamp()`，保证大屏不空、小屏不挤。
- 黑底不是每页强制主题，可只用于首页精选区和作品档案。
- 大标题负责识别，元信息负责理解，两者不能都做成装饰。
- 图片比例至少准备 `4:5`、`16:10` 两种，不能依赖所有素材同尺寸。

## 6. 明确不迁移的部分

以下属于原站未收尾或不适合 Formulasearch 的部分：

- 超过 22,000px 的首页长度。
- 同一身份信息和装饰栏在每个区块反复出现。
- `Palmer` 模板标题、`Use for Free`、Framer 徽标等模板残留。
- 作品编号跳号、重复路由和错误外链。
- 中英文重复但没有信息增量的双语排版。
- 只有成品图、没有问题、职责、过程与结果的案例页。
- 依赖鼠标位置才能理解内容的导航。
- React/Framer 客户端与服务端渲染不一致造成的闪烁风险。

---

## 7. 放进现有三套演示的位置

### Editorial Archive

- 首页精选 4 项使用不对称网格。
- 完整档案仍保留 List / Overview 双视图。
- 悬浮聚焦只用于 Overview，不污染高密度清单。

### Tactile Asset Platform

- 不使用这套网格作为完整货架。
- 可把“当前聚焦、其他降权”的规则用于资产桌面的选中状态。

### Layered Visual Hub

- 这套交互最适合该方向。
- 使用强首屏 + 4 个精选项目 + 文本索引，不能继续堆完整长首页。

## 8. 开发验收清单

- [ ] 首屏同屏可见身份、五入口和一个真实内容。
- [ ] 精选区最多 4-6 项，完整内容另有索引。
- [ ] 每项点击前可识别类型、标题和状态。
- [ ] 悬浮与键盘焦点反馈一致。
- [ ] 移动端取消依赖悬浮的隐藏信息。
- [ ] 关闭动画后仍可完整浏览。
- [ ] 图片未加载时仍显示标题和类型。
- [ ] 不使用滚动劫持、加载片头和默认声音。
- [ ] 详情页写清问题、角色、过程和结果，或提供真实可用入口。
