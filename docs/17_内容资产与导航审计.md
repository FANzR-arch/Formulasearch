## 3. 推荐一级导航

```text
Blog        Projects        Skills        Lab
```

左上角 Logo 返回首页；首页本身承担 About。X、GitHub、邮箱、主题切换继续作为图标，不占文字导航。

### Blog

```text
AI & Tools          AI 教程、工具与实践
Aesthetic Systems   视觉拆解、提示词与方法
Notes               个人观察与思考
```

Blog 首页仍然承担“最近发布”；此处三类用于直达已存在的文章集合。Archive 保留在 Blog 内部分区导航，不占用首级悬浮菜单。每篇正文有独立 URL。

### Projects

```text
Products & Tools    Seedo / RZFrame / UPet / X-studio
Websites            网站、交互页面、客户与伙伴项目
```

Projects 只展示已经有明确产出或可说明状态的项目。Current Focus、视觉系统和原型作为 Projects 页面内部的状态或筛选，不增加菜单层级。私人仓库、客户项目和合作项目必须单独确认公开边界。

### Skills

```text
Design Skills       Phil Design Skills
Agent & Workflows   agent-worklog、Numerologist Skills、工作流
All Skills          完整 Skills 索引
```

Skill 页解决“能否直接拿走使用”，对应文章解决“为什么这样做、如何形成”。两者互相链接，不合并成同一种页面。

### Lab

```text
Experiments         Aesthetic Formulas、动态视觉与原型
Courses             SEO/GEO、Price Action 等课程入口
Now                 最近在学、在测试、在推进什么
```

Lab 用来容纳真实但尚不足以升级为一级栏目的内容。Photography 与 Architecture 已确定使用独立图标进入，不放进 Lab 菜单。某一类长期积累到足够规模后，可以从 Lab 独立出来。

## 4. 图标导航

文字导航之后使用分隔线，放置低频但有明确内容的站内入口；再用第二条分隔线区分外部平台与界面功能：

```text
Blog  Projects  Skills  Lab  |  Photography  Architecture  |  X  GitHub  Mail  Theme
```

界面只显示图标，悬浮或键盘聚焦时显示名称：

| 入口 | 图标来源 | 推荐图标 |
|---|---|---|
| Photography | Lucide Icons | `Aperture`，备选 `Camera` |
| Architecture | Lucide Icons | `DraftingCompass` |
| Mail | Lucide Icons | `Mail` |
| Theme | Lucide Icons | `Sun` / `Moon` |
| GitHub | GitHub 品牌图标 | 保留当前官方轮廓标志 |
| X | X 品牌图标 | 保留当前 X 标志 |

GitHub 和 X 属于品牌标志，不使用 Lucide 替代。搜索和 RSS 等工具等真实页面上线后再增加，首版不为了填满图标区添加入口。

## 5. 悬浮菜单交互原则

- 鼠标悬浮一级导航时弹出小型菜单，一级标题本身仍可点击并进入栏目总览。
- 每个菜单控制在 4–6 项；只展示一层子项，不继续嵌套第三级菜单。
- 每项采用“短标题 + 一行解释”，避免大面积图片式 Mega Menu 抢过背景和首页内容。
- `Current Focus`、`Latest`、`Now` 可以使用小圆点强调，其余保持低存在感。
- 桌面端支持悬浮和键盘焦点；移动端改为点击展开的手风琴菜单。
- 关闭菜单要有短暂容错区，避免鼠标从导航移到菜单时意外消失。
- 尚无真实内容的栏目不显示；不能为了让菜单对称而创建空页面。Photography 与 Architecture 当前只提供档案入口与整理说明，不伪造尚未精选的作品。

## 6. 不建议作为一级导航的项目

- `About`：首页已经是完整的个人介绍。
- `Sponsors`：目前只有赞助动作，还没有独立赞助体系与名单；先放首页底部或图标入口。
- `Talks`：没有形成稳定的演讲、幻灯片和视频档案。
- `Services`：网站搭建、SEO/GEO 等合作能力先放在 Projects 与联系区域；内容足够后再独立。
- `Photography`：以图标入口独立存在，不占文字导航。
- `Architecture`：以图标入口独立存在，不与当前 Projects 主线混在一起。
